1. INTRODUCTION                                          *codeview-introduction*
                                                                    *codeview*

codeview shows the changes of a commit, or of a range of commits. You browse
the changed files in a sidebar, read the diffs inline or side by side, and
write comments on the lines. You can export the comments as markdown.

This release selects the revisions of a review, lists the changed files in a
sidebar, and shows an inline diff of each file. The side-by-side diff and the
comments come with the next milestones.

==============================================================================
2. REQUIREMENTS                                          *codeview-requirements*

- Neovim 0.11 or later.
- git, for the git backend.
- jj, for the jj backend (optional).
- gh, for GitHub pull request review (optional).

==============================================================================
3. SETUP                                                        *codeview-setup*

The plugin works without a setup call. Every option then holds its default
value.

To change an option, call setup(): >lua

    require("codeview").setup({
      diff = { style = "split" },
    })
<
                                                          *codeview.setup()*
codeview.setup({opts})
    Merge {opts} into the defaults, validate the result, and store it.

    Return: ~
        The active configuration, or nil and a message when {opts} is invalid.

                                                          *codeview.config()*
codeview.config()
    Return the active configuration table.

                                                                  *g:codeview*
You can also set the variable `vim.g.codeview` before the plugin loads. The
plugin then calls setup() with that table: >lua

    vim.g.codeview = { sidebar = { position = "right" } }
<

4. COMMANDS                                                  *codeview-commands*

                                                                   *:CodeView*
:CodeView {rev}
    Review one commit. The base of the review is the parent of {rev}. For the
    first commit of the repository the base is the empty state.

    The command sends the argument to the backend as it is. A revision
    argument can hold spaces, for example `main@{2 days ago}`.

    Examples: >vim

        :CodeView HEAD
        :CodeView HEAD~3..HEAD
        :CodeView main...feature
<
:CodeView {rev}..{rev}
    Review the changes between the two revisions. The left side is the base.
    It is not part of the review.

:CodeView {rev}...{rev}
    Review the changes since the merge base of the two revisions.

:CodeView
    Open the commit picker. Select one commit to review it.

:CodeView!
    Open the picker in the range mode. Select the first commit of the range,
    then the last commit. Both commits are part of the review. The second list
    holds only the descendants of the first commit.

                                                              *:CodeViewClose*
:CodeViewClose
    Close the review session. The command closes the windows and the buffers
    of the session.

                                                              *:CodeViewFiles*
:CodeViewFiles
    Open the changed-files sidebar and put the cursor in it. The command
    closes the sidebar when the sidebar is open.

5. SESSIONS                                                  *codeview-sessions*

A session holds the backend handle, the resolved range, the commits of the
range, and the files that the range changes. The plugin keeps one session. A
second open closes the session that runs. A failed open keeps it.

The session sends these events: >

    User CodeViewSessionOpened      a session opened
    User CodeViewSessionRefreshed   a session read its data again
    User CodeViewSessionClosed      a session closed
<
The `data` field of the event holds plain values only: >

    data.id         number of the session
    data.spec       text that names the range
    data.files      number of changed files
    data.commits    number of commits in the range
<
Neovim copies the payload of a User event, so the payload cannot hold the
session object. To use the session methods, read the session with
|codeview.session()|: >lua

    vim.api.nvim_create_autocmd("User", {
      pattern = "CodeViewSessionOpened",
      callback = function(event)
        print(event.data.spec, require("codeview").session():summary())
      end,
    })
<
The close event comes after the session ended. |codeview.session()| gives nil
in that handler.

6. SIDEBAR                                                    *codeview-sidebar*

The sidebar shows the files that the range of the session changes, as a tree.
It opens with the session, at the side that `sidebar.position` names. Set
`sidebar.auto_open` to false to open the sidebar with |:CodeViewFiles| only.

The first two lines are the header. The first line holds the range. The
second line holds the number of files and the number of commits. The tree
comes after an empty line: >

    9b2688a5..ec056be0
    4 files, 2 commits

      ▾ dir
      │   renamed.txt ← nested.txt R
    ▸   a.txt M
        added.txt A
        keep.txt D
<
The tree holds one node per directory and one node per file. A chain of
directories with one child each becomes one node, for example
`lua/codeview/vcs`. Directories come before files, and both come in
alphabetical order.

Each file line ends with a status mark: >

    A    the range adds the file
    M    the range changes the file
    D    the range deletes the file
    R    the range renames the file
    C    the range copies the file
    T    the range changes the type of the file
    U    the file is unmerged
    ?    the backend gave another status
<
A rename line and a copy line also show the old path, after an arrow. A
directory that hides its children shows the marks of the files below it.

The marker "▸" and the highlight group |hl-CodeViewCurrent| mark the file that
the diff view shows. The marker moves with every file that you open. A
directory that hides the marked file opens again.

                                                     *codeview-sidebar-keymaps*
The sidebar buffer holds these maps. |codeview-config| names the keys: >

    <CR>    open the file under the cursor, or toggle a directory
    <Tab>   toggle the directory of the line under the cursor
    zR      show the children of every directory
    zM      hide the children of every directory
    ]f      open the next file
    [f      open the previous file
    q       close the review session
<
The next-file key and the previous-file key follow the order of the tree.
They step over the directory nodes, and they also reach a file in a directory
that hides its children.

The buffer of the diff view holds the maps `]f`, `[f`, and `q`. You walk
through the files without a move back to the sidebar. Each key press moves one
file, also while the backend still reads the file of the last press.

                                                       *codeview-sidebar-icons*
The tree uses text icons from `sidebar.icons`. The plugin needs no icon font
and no devicons plugin. For a terminal without support for the default
icons, set plain characters: >lua

    require("codeview").setup({
      sidebar = {
        icons = {
          expanded = "-",
          collapsed = "+",
          file = " ",
          guide = "|",
          current = ">",
        },
      },
    })
<

7. DIFF VIEW                                                     *codeview-diff*

The diff view shows one changed file in the main window. It reads both sides
of the file from the backend and compares them with |vim.diff()|. This release
holds the inline style: one unified diff in one buffer.

The buffer is read-only. Its filetype is `codeview-diff`. The buffer variable
`b:codeview_filetype` holds the filetype of the file itself: >

    @@ -1,6 +1,6 @@
     line 01
     line 02
    -line 03
    +line 03 changed
     line 04
     line 05
     line 06
    ⋯ 20 unchanged lines
    @@ -27,7 +27,7 @@
     line 27
<
The first character of a line is the marker. A space marks an unchanged line,
`-` marks a removed line, and `+` marks an added line. The status column shows
the line number of the old file and the line number of the new file.

A line that only one side holds shows one number. The plugin highlights a
removed line with |hl-CodeViewDiffDelete| and an added line with
|hl-CodeViewDiffAdd|. With `diff.word_diff` the changed part of a line also
gets |hl-CodeViewDiffText|.

                                                        *codeview-diff-context*
The view shows `diff.context` unchanged lines around each hunk. It hides a
longer unchanged section behind one filler row: >

    ⋯ 20 unchanged lines
<
A section that hides fewer than two lines stays open, because the filler row
costs as many screen rows as the lines that it hides.

Put the cursor on the row and press `za` to show the hidden lines. A second
press hides them again. `zR` shows every hidden line of the file, and `zM`
hides them all again. The hunk header keeps the line numbers of the collapsed
form, because the header names the position of the hunk in the file.

A file without a text diff shows one note instead of a diff: >

    The file has no changes.    a rename or a copy without a content change
    The file is empty.          both sides hold no line
    Binary file. It has no text diff.
<
                                                        *codeview-diff-keymaps*
The diff buffer holds these maps. |codeview-config| names the keys: >

    ]h      jump to the next hunk
    [h      jump to the previous hunk
    za      show or hide the section under the cursor
    zR      show every hidden line
    zM      hide every section again
    ]f      open the next file
    [f      open the previous file
    q       close the review session
<
The diff view sends one event: >

    User CodeViewFileOpened    a file opened in the view
<
The `data` field of the event holds these values: >

    data.session    number of the session
    data.index      position of the file in the file list
    data.path       path of the file
    data.status     status of the file in the range
    data.buf        buffer that holds the diff
<
                                                        *codeview-diff-linemap*
The view keeps a line map. The map holds one record per buffer row, with the
kind of the row, the line in the old file, the line in the new file, and the
hunk of the row. Read the map with |codeview.view()|: >lua

    local map = require("codeview").view().map
    local row = vim.api.nvim_win_get_cursor(0)[1]
    print(map:kind(row), map:file_line(row))   -- "add", 12, "new"
    print(map:buf_row(12, "new"))              -- 5
<

8. LUA API                                                        *codeview-api*

                                                             *codeview.open()*
codeview.open({spec}, {opts}, {cb})
    Open a review session for {spec}. {spec} is revision text such as "HEAD"
    or "main..feature", or a table with resolved revisions.

    {opts} accepts these fields: >lua

        {
          repo = nil,     -- repository handle, to skip the detection
          dir = nil,      -- directory for the detection, cwd by default
          backend = nil,  -- "auto" | "git" | "jj", the config value by default
        }
<
    Without {cb} the call blocks and returns `session, err`. With {cb} the
    call returns at once and calls `cb(session, err)`.

                                                             *codeview.pick()*
codeview.pick({opts}, {cb})
    Open the commit picker. Set `opts.mode` to "range" to ask for two picks.
    The callback gets nil and nil when the user cancels the picker.

                                                          *codeview.session()*
codeview.session()
    Return the session that runs, or nil.

                                                            *codeview.close()*
codeview.close()
    Close the session that runs. Return false when no session runs.

                                                          *codeview.sidebar()*
codeview.sidebar()
    Return the sidebar that runs, or nil.

                                                     *codeview.open_sidebar()*
codeview.open_sidebar({opts})
    Open the changed-files sidebar for the session that runs. {opts} accepts
    a `session` field and a `focus` field. The call returns `sidebar, err`.

                                                    *codeview.close_sidebar()*
codeview.close_sidebar()
    Close the sidebar. The session stays open. Return false when no sidebar
    is open.

                                                   *codeview.toggle_sidebar()*
codeview.toggle_sidebar({opts})
    Close the sidebar when it is open, and open it when it is closed. Return
    the state after the call.

                                                             *codeview.view()*
codeview.view()
    Return the state of the diff view, or nil when no file is open. The state
    holds the path, the status, the diff, the line map, the buffer, and the
    window.

                                                        *codeview.open_file()*
codeview.open_file({index}, {opts}, {cb})
    Open one changed file of the session in the diff view. {index} is the
    position of the file in the file list. {opts} accepts a `session` field.

                                                        *codeview.next_hunk()*
codeview.next_hunk({opts})
    Move the cursor to the first row of the next hunk. Set `opts.wrap` to true
    to continue at the first hunk. Return the row, or nil.

                                                        *codeview.prev_hunk()*
codeview.prev_hunk({opts})
    Move the cursor to the first row of the previous hunk. Set `opts.wrap` to
    true to continue at the last hunk. Return the row, or nil.

                                                   *codeview.toggle_context()*
codeview.toggle_context({id}, {expanded})
    Show or hide the lines of a collapsed section. Without {id} the call acts
    on the section under the cursor. Return false without a section.

A session answers these calls: >lua

    session:label()          -- text of the range
    session:summary()        -- range, file count, and commit count
    session:changed_files()  -- list of changed files
    session:file(index)      -- one changed file
    session:index_of(path)   -- position of a path in the list
    session:refresh(cb)      -- read the files and the commits again
    session:close()          -- close the session
<

9. CONFIGURATION                                               *codeview-config*

Defaults: >lua

    {
      backend = "auto",              -- "auto" | "git" | "jj"
      diff = {
        style = "inline",            -- "inline" | "split"
        context = 3,                 -- unchanged lines around a hunk
        max_lines = 20000,           -- ask before a larger diff
        word_diff = true,            -- highlight changed words
      },
      sidebar = {
        position = "left",           -- "left" | "right"
        width = 40,
        auto_open = true,
        icons = {
          expanded = "▾",            -- directory that shows its children
          collapsed = "▸",           -- directory that hides its children
          file = " ",                -- file, to keep the names in one column
          guide = "│",               -- indent guide of one tree level
          current = "▸",             -- file that the diff view shows
        },
      },
      comments = {
        dir = stdpath("config") .. "/review",
        display = "virtual",         -- "virtual" | "float"
        sign = "▌",
      },
      export = {
        register = "+",
        template = false,            -- false uses the built-in renderer
      },
      keymaps = {
        open_file = "<CR>",
        toggle_node = "<Tab>",
        expand_all = "zR",
        collapse_all = "zM",
        next_file = "]f",
        prev_file = "[f",
        next_hunk = "]h",
        prev_hunk = "[h",
        expand_context = "za",
        toggle_style = "<leader>ct",
        comment = "<leader>cc",
        delete_comment = "<leader>cd",
        close = "q",
      },
      log_level = vim.log.levels.WARN,
    }
<
Set a keymap to false to disable it. setup() rejects an unknown key, and
reports the name of the key.

10. HIGHLIGHTS                                             *codeview-highlights*

Every group of codeview links to a standard group. The link is a default
link, so your own link or your own colors win. The plugin sets the links
again after a colorscheme change.

                                                        *hl-CodeViewCurrent*
                                                        *hl-CodeViewAdded*
                                                        *hl-CodeViewModified*
                                                        *hl-CodeViewDeleted*
                                                        *hl-CodeViewRenamed*
                                                        *hl-CodeViewDiffAdd*
                                                        *hl-CodeViewDiffDelete*
                                                        *hl-CodeViewDiffText*
>
    CodeViewTitle          Title        range in the sidebar header
    CodeViewCount          Comment      counts in the sidebar header
    CodeViewHint           Comment      text of an empty list
    CodeViewDir            Directory    directory node, icon, and old path
    CodeViewIndent         NonText      indent guides of the tree
    CodeViewCurrent        CursorLine   line of the file in the view
    CodeViewMarker         Special      marker of the file in the view
    CodeViewAdded          Added        status mark A
    CodeViewModified       Changed      status mark M
    CodeViewDeleted        Removed      status mark D
    CodeViewRenamed        Special      status mark R
    CodeViewCopied         Special      status mark C
    CodeViewTypechanged    WarningMsg   status mark T
    CodeViewUnmerged       ErrorMsg     status mark U
    CodeViewUnknown        Comment      status mark ?
    CodeViewDiffAdd        DiffAdd      added line of a diff
    CodeViewDiffDelete     DiffDelete   removed line of a diff
    CodeViewDiffText       DiffText     changed part of a line
    CodeViewDiffHunk       Title        hunk header of a diff
    CodeViewDiffFold       Folded       row of a collapsed section
    CodeViewDiffNumber     LineNr       line numbers of the status column
    CodeViewDiffMessage    Comment      note of a file without a text diff
<
To change a color, set the group after your colorscheme: >lua

    vim.api.nvim_set_hl(0, "CodeViewCurrent", { link = "Visual" })
<

11. HEALTH                                                     *codeview-health*

Run |:checkhealth| codeview. The report shows: >

    - the Neovim version, against the minimum version
    - the plugin version and the state of setup()
    - the result of the configuration validation
    - the git, jj, and gh executables with their versions
<
